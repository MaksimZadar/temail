# temail UI design (phase 2, actions added in phase 4)

Status: accepted direction. Setup wizard, mailbox view, mail actions (section 10) and AI label suggestions (section 11) implemented.

**Principle.** temail is a modern desktop app first. Everything works with the mouse alone: visible buttons, clickable rows and folders, hover and focus states, tooltips. Vim-style keys are an optional accelerator layered on top, never required. It must not look like a terminal: no monospace UI, no mode line, no key-hint bar as the main interface.

## 1. Visual direction

Dense but friendly (think Linear, Thunderbird's compact view), quiet, content first.

- **Type.** IBM Plex Sans for all UI and message text (13 px UI, 14 px message body, 12 px small). JetBrains Mono only for fingerprints, code and key caps. Both are self-hosted through `@fontsource` (no CDN). Tabular numerals for dates and counts.
- **Density.** List rows 28 px, 4 px grid, 1 px hairlines, 6-12 px corner radius on cards and dialogs, soft shadows only on overlays. A roomier row size is a later setting.
- **Theme.** Follows the system (`prefers-color-scheme`); `:theme auto|light|dark` in the palette overrides it through `<html data-theme>`.
- **Tokens** (`frontend/src/styles/tokens.css`; the tests check that both themes define them and that text pairs meet WCAG AA 4.5:1):

| Token | Light | Dark |
|---|---|---|
| `--bg` | #fafaf8 | #14161a |
| `--bg-pane` | #f2f1ed | #191c21 |
| `--bg-raised` (cards, dialogs) | #ffffff | #1f2329 |
| `--fg` | #1d1f23 | #d8dbe0 |
| `--fg-dim` | #5c616a | #8d95a0 |
| `--line` | #dcdad3 | #2a2e36 |
| `--accent` (violet) | #6d41d8 | #a78bfa |
| `--accent-fg` (text on accent) | #ffffff | #14161a |
| `--sel-bg` | accent at 14% | accent at 16% |
| `--danger` / `--ok` | #b42f26 / #1d7a46 | #f0847b / #6fcf97 |

- **Panes as cards.** Each pane is its own card on a slightly tinted canvas: 8 px margin on every side and between panes, 8 px corner radius, a normal 1 px `--line` border. The focused pane gets the whole border in the violet accent plus a faint 4 px ring (a 2 px `Highlight` outline in forced-colors/high-contrast mode); only one pane is focused at a time. The highlight follows the keyboard (`h`/`l`, `b`, `j`/`k`) and the mouse (clicking anywhere in a pane or focusing something inside it); clicking a folder keeps the highlight on the folder pane. Inner controls inside a pane don't draw a second ring around the list or frame (the pane border is the indicator); buttons and inputs keep their own focus ring. The border colour fades over 120 ms, and not at all with reduced motion.
- **States.** Unread: bold sender and subject plus a small violet dot. Read: regular weight, dimmed subject. Selected row: `--sel-bg` background plus a 2 px violet bar on the left. Hover: a lighter tint of the same colour. Focus: 2 px violet outline, `:focus-visible` only. Never colour alone: unread is weight plus dot, selected is bar plus tint.

## 2. Layout (implemented)

- A toolbar on top (folders toggle, a back button in single-pane mode, the folder title, a filter field, refresh, commands, shortcuts), three panes (folders and labels, message list, message view), and a slim footer. Every action has a visible button with a tooltip that shows its shortcut, for example "Refresh (g r)".
- **Footer.** One stable status button on the left, never flapping between folders: "Syncing folders · 3 of 14" with a thin overall bar, then "Downloading messages · 3 of 14 folders", then "Synced · just now" (relative time). If some folders failed, a "Some folders couldn't sync" link appears next to it. Clicking the status opens a sync panel (Esc, a click outside or Close dismisses it and focus returns to the button) that lists every folder: active first, then waiting, done, failed with the reason, each with its state, counts and a small progress bar. The same list is shown in the main placeholder. On the right, a quiet "Shortcuts ?" button. No mode name and no key-hint line.
- **Live state.** After the first sync, Go keeps watching. `SyncStatus.running` now means the first sync only; `watching` means the live watcher is up. The footer shows "Syncing…" (first sync only, with the progress bar), then "Live" only while the live connection is up (the tooltip says "New mail appears instantly; read and star changes made elsewhere may take a few minutes"), otherwise "Up to date · checked 2 min ago" with a small "polling" hint (hover for why). `running` is read from the status, not guessed from events: progress events also fire for watcher checks, so a stray one never leaves a stuck spinner. **Sync now** (toolbar button, `g r`, the palette, and the sync panel) calls `SyncService.Start()`; while watching that just asks for a check, and during the first sync it says "Already syncing". Resyncs after a change never flip it back to Syncing. A watch error shows "Sync failed".
- **Cache size.** To the right of the sync status, the footer shows "Cache 1.2 GB" (1024-based units, one decimal below 10, tabular digits, fixed minimum width). Hovering shows "N messages · N bodies cached". It comes from `MailService.CacheInfo()`, loaded on start, right after `sync:done`, and at most every 5 s while syncing. If the call fails the item is hidden. It is not a live region.
- **Sync updates.** The store (`stores/sync.svelte.ts`) keeps one entry per folder from `sync:progress` (seeded from `ListMailboxes`, so folders show as waiting), plus an aggregate (folders done, messages cached, overall percent that never steps backwards). Events are coalesced and published at most every 250 ms. Screen readers hear only "Sync started" / "Sync finished" / "Sync failed" through a polite live region, not each step.
- **Key prefixes.** While a prefix such as `g` is pending, the which-key popover stays up with no timeout. A chip in the footer also shows the prefix. It closes when you press a valid follow-up, press Esc, press an invalid key (which only cancels, so a typo never triggers something else), click elsewhere, or click one of its entries (entries are buttons). A polite live region says "g pressed. Options: …" once.
- **Panes.** Drag handles (also focusable, arrow keys resize); widths and the folder-pane toggle are saved in `localStorage`. The folder pane starts hidden on windows under 1000 px (toggle with the toolbar button or `b`; an icon rail is not built). Below 800 px only one pane shows at a time, with a Back button (also `h` and `Esc`). Folders, rows and buttons are all clickable. Each folder shows its **unread count** as a violet badge (hidden at 0) with a bold name; Drafts shows how many drafts there are instead; the tooltip gives "N unread · N messages". Folders are ordered Inbox, Drafts, Sent, Archive, Spam, Trash, then folders, then labels.
- **Virtualised list.** Fixed row height, windowed rendering with 10 rows of overscan, pages of 50 using the `next` cursor, the cursor tracked by (mailbox, uidValidity, uid) so a sync refresh doesn't move it. `ErrStaleEpoch` reloads the list and shows a toast.
- Sync state comes from `sync:progress`, `sync:done` (may carry `mailboxErrors`, shown as "some folders failed") and `sync:error`. The list reads from the cache and never waits for sync.

## 3. Keyboard (optional accelerator)

Keys are ignored while typing in any input, during IME composition, and for Ctrl/Alt/Meta combinations the browser or OS owns (only Ctrl-d/u/f/b are ours). `Esc` leaves a field. Counts (`5j`) and sequences (`g i`) wait with no timeout; `Esc`, an invalid key or a click elsewhere cancels them. The single table in `frontend/src/lib/keys/keymap.ts` drives the handler, the `?` overlay and the which-key popover.

**Active** (read-only): `j`/`k` move, `gg`/`G` first/last (`12G` = line 12), `Ctrl-d`/`Ctrl-u` half page, `Ctrl-f`/`Ctrl-b` page, `h`/`l` pane focus (`Tab` keeps its normal meaning, so keyboard users are never trapped), `b` show or hide folders, `Enter`/`o` open, `[`/`]` previous/next message, `g i/s/d/t/a/j` go to Inbox/Sent/Drafts/Trash/Archive/Spam, `g l` pick any folder or label, `g r` refresh, `g ,` Settings, `g h` plain text/HTML, `g x` links in this message, `y` copy sender, `/` filter the loaded messages of the folder by subject or sender (Esc clears), `g u` recent activity, `:` command palette (includes "Go to <folder>", "Recent activity", "Undo last action"; `g l` opens it that way), `?` shortcuts. In the setup wizard: `Enter` continues, `Esc` goes back, `?` and `:` work.

**Actions** (phase 4, see section 10): `e` archive, `d` trash (`#` is an alias), `!` spam (not spam when you are in Spam), `m` move to a folder, `;` labels, `u` toggle read, `s` toggle star, `S` suggest labels (AI, see section 11), `z` undo, `x` select a row, `v` select a range, `Esc` clears the selection, `g u` recent activity. `U` is unbound. Counts are ignored on actions (the hint says "Counts don't apply to actions").

**Reserved for later** (the keys stay free; `i` load remote images is also reserved, see section 5, and is listed greyed in `?`; pressing one shows "Not available yet"): `r`/`R` reply drafts (phase 5). Lowercase acts on the current item; uppercase is the broader variant. Remapping in a config file comes later.

**Overlays.** `Esc` closes every overlay (shortcuts, commands, sync panel). `q` also closes the shortcuts and sync panels (never in the commands field, where it is just a letter), and `?` closes the shortcuts again. Overlays keep `Tab` inside them and give focus back when they close. The command palette (`:`) shows at most 5 results at a time, filtered as you type (name, aliases, and loose in-order matches, best first, matched letters highlighted); arrows or `Ctrl-n`/`Ctrl-p` move and scroll the window, `Enter` runs, a click works, and it says "No matching commands" when nothing fits.

**Discoverability, gently.** Tooltips with shortcuts on buttons, the `?` overlay (also the footer button), the which-key popover, and the command palette listing commands. No always-visible hint bar. The setup wizard shows one short line, "Enter continues. Esc goes back."

**Accessibility.** Panes are landmarks; the list is a listbox with `aria-activedescendant` and `aria-posinset`/`aria-setsize`; folder names include the unread count. Errors use `role="alert"`; sync and status use `aria-live="polite"`. Focus moves to the step title when the wizard changes step, overlays trap focus and restore it on close, and a visible focus ring is always shown. All text meets AA contrast in both themes. `prefers-reduced-motion` turns off animations (the sync pulse and transitions). Sizes use `rem`. Single-key shortcuts can later be turned off (WCAG 2.1.4); every function has a mouse path.

## 4. Setup wizard (implemented)

A centred card, one step per screen, "Step N of 4", plain short copy. Driven by `GetStatus`, so a restart resumes at the first unmet step. Enter continues where that is safe, Esc goes back. Enter never trusts a certificate; that needs a click or Enter on the focused button.

1. **Welcome and checks.** Explains that mail is read through Bridge on this computer. Live checks: Bridge reachable, password storage ready. "Check again" and a disabled Continue until both pass.
2. **Bridge account.** Username and password (from Bridge's Mailbox details, not the Proton password). Advanced: host (`127.0.0.1`), IMAP 1143, SMTP 1025, connection type (STARTTLS default, or SSL/TLS). The host is loopback only. When an account already exists, the password may be left empty to keep the saved one. The password is cleared from the form as soon as `SaveAccount` returns, success or not; it is never kept anywhere else.
3. **Check this connection.** `ProbeCert` then `TrustCert(fingerprint, replace)`. Explains that Bridge makes its own certificate, shows the fingerprint (mono, copy button), what it is, and how to compare it with the one exported from Bridge. If a different certificate is already saved (`already_pinned`), the button becomes "Replace saved certificate" with a short warning. If it changed between probe and trust, or the settings changed, nothing is saved and the copy says so.
4. **Test and finish.** `TestConnection`, then "Connected. Your mail will start loading now." and "Open mailbox".

**Errors.** Each appears as a banner with `role="alert"` and a recovery button; no secret is ever shown. Keyring unavailable (unlock KWallet / check Credential Manager; back to checks), Bridge not running (open Bridge and sign in; retry), wrong password (use Mailbox details; back to the password), not trusted yet or certificate changed (review the certificate), invalid settings (edit them), no saved password, and a generic fallback. All `TestConnection` categories are mapped (`frontend/src/lib/setup/errors.ts`) and tested.

## 5. Safe email rendering (implemented)

- `HTMLBody` (already sanitised in Go) goes in `<iframe sandbox srcdoc>` with an empty sandbox list: no scripts, no same-origin, no forms, no popups; a meta CSP `default-src 'none'; img-src data: cid:; style-src 'unsafe-inline'` (`https:` is added to `img-src` only after the user loads images for that message).
- **Scrolling and focus (decided).** A sandboxed frame without `allow-same-origin` cannot be scrolled or watched by the app, and keys typed inside it never reach the app (that is what made `h` and `Esc` stop working). So the app never puts focus inside the frame: `Enter`, `o` and `l` focus a host element of the message pane, the frame has `tabindex="-1"`, and `h`, `Esc`, `b` and the other keys keep working. The mouse wheel, touchpad and scrollbar scroll the frame natively. For the keyboard, the first scroll key (`j`, `k`, `Ctrl-d/u/f/b`, `gg`, `G`) switches that message to plain text, which the app scrolls itself, and says so ("Plain text, so the keys can scroll. g h switches back."). If you click inside the frame anyway, a bar appears ("The message has your keyboard…") with a "Back to keys" button; `Tab` or a click outside also works. No scripts or `allow-same-origin` are added. *Option for later:* `allow-same-origin` without `allow-scripts` would let the app scroll the formatted view directly (no script can run in the frame); it is not enabled because it relaxes the sandbox.
- **Remote images.** Go removes remote images before the message reaches the UI, so the pane shows a quiet note, "Remote images are blocked.", with no button. *Future work:* a per-message "Load images" flow needs Go support (a fetch path that returns the images as `data:` URLs or an allow-listed proxy); the frame CSP would then add those `data:` images only. `cid:` images are not resolved yet and show their alt text.
- **Plain text.** A Formatted / Plain text switch (`g h`) appears when both parts exist; messages with only text, or only HTML, show what they have (plain text from HTML is a simple extract). Plain text is wrapped, proportional, URLs not linked.
- **Links (decided).** Nothing inside the frame can navigate: before rendering, the host (in an inert DOM) removes every `href`, drops scripts, frames, forms, base tags and `on*` attributes, and collects http, https and mailto links. They appear in a "Links (n)" list (`g x`) that shows the text and the real address; clicking one opens it in the system browser through the Wails runtime (`Browser.OpenURL`). A confirm appears only when the link text shows an address (for example `paypal.com`) that is not where the link goes; plain words like "Read more" open directly because the real address was already on screen.
- Attachments are listed with name, type and size; Download calls `GetAttachment`, turns the bytes into a Blob and saves it through the browser's download handling; no path is ever chosen by the page. Large files show "Too large to download here".

## 7. Decided answers

`l` is pane focus (labels use `;` later). Three panes by default, single pane on small windows. Flat list (no threads). Follow the system theme. `/` is a client-side subject filter. Bundled Plex Sans and JetBrains Mono. Confirm link opening only when the text and the target differ. Remappable keys later. Violet accent.

## 8. Known gaps

- **Remote images** cannot be loaded per message yet (section 5).
- **Live changes (implemented).** `sync:changed` is coalesced for 250 ms. It refreshes the counts, and the head of the open list only if that mailbox changed. The cursor stays on its message (or on its neighbour if that one was removed), the scroll position is kept, messages that disappeared are removed, and an open message that left the folder stays on screen with "This message is no longer in this folder." The open message's folder and label chips are re-read when they may have changed.

Message headers carry `mailboxes` (the folder or system mailbox and labels the message is in). The message pane shows them as chips under the header (a neutral chip for the folder, violet-tinted chips for labels, each with a tooltip); clicking one jumps to it like a `g` jump. The list shows up to two compact label chips per row when the list is at least 520 px wide, never repeating the label you are viewing.

## 10. Mail actions (implemented)

Actions call `ActionService.Apply` with stable message ids (the `internalId` of the message header, never a UID). Cache, folder membership and counters are updated in Go; the UI re-reads the list afterwards and keeps `actions:done` (coalesced, 250 ms) as a refresh hint next to `sync:changed`. The cursor stays on its message key through every refresh.

- **What an action targets.** The selection if there is one; otherwise the open message when the message pane is focused; otherwise the cursor row (list focused). Messages without an id yet are skipped with a hint.
- **Selection.** `x` toggles the cursor row, `v` starts a range that follows the cursor (like vim visual mode; `v` or `x` ends it and keeps it), `Esc` clears. Ctrl-click toggles a row and Shift-click selects from the cursor row. Selected rows get a violet tint, a 2 px violet bar and a check mark; the toolbar shows "N selected" with a clear button. The selection belongs to the folder it was made in.
- **No confirmation prompts.** All actions are reversible, so there is an undo toast instead. Nothing is ever deleted for good (trash only).
- **Batches.** Go takes at most 100 messages per call. Bigger batches are sent in chunks of 100, one after another, and the results are merged into one toast.
- **While it runs.** The affected rows show a small spinner and dim; the list is re-read from the store when Go answers (no optimistic changes). After archive, trash, spam, not spam and move, the cursor goes to the next message (the previous one at the end of the list); if you were reading, the next message opens.
- **Move** (`m`) opens a picker in the command-palette style: 5 rows, filtered as you type, listing `Folders/*` plus Archive, Trash and Spam (those use their own action types). **Labels** (`;`) opens a similar picker with checkboxes; labels the targets already have are ticked, labels on only some are shown as "mixed". Apply sends only the differences as `add_label` / `remove_label`.
- **Toast.** "Archived 3 messages · Undo" for 8 s (paused while hovered or focused). Undo reverts exactly that action: it calls `Undo(id)` for each id in the result's `auditIds` (the undoable rows only), so a newer action never gets undone by mistake. With no undoable rows there is no Undo button. `z`, the toolbar and the palette call `UndoLast` (the newest action). An error toast stays 16 s: "2 of 5 failed: <reason>" (the most common reason, and how many others). A copy-only archive, trash, spam or move says "Created the copy, but the original is still in INBOX — it will be resolved after the folders sync".
- **Undo refusals.** Go returns no error but a `code`: `not_found` and `wrong_account` show "Nothing to undo", `already_undone` "Already undone", `not_undoable` "This action can't be undone", `diverged` "This message changed since then, so it can't be undone safely". The UI never matches error text.
- **Activity.** `g u`, the toolbar clock button or the palette command "Recent activity" lists the last 50 actions, one row per batch ("Archived 3 messages", with the time). Undo is enabled only when the row has `auditIds` and no `code`; it undoes the whole batch. Rows that cannot be undone show the reason as a tooltip.
- **Mouse.** Toolbar buttons (archive, trash, spam, move, labels, read, star, undo, activity), quick actions that appear on a row on hover or when it is the cursor row, and a right-click menu on rows. All have tooltips with the key. A quick action on a selected row applies to the whole selection.

## 9. Settings and AI providers (implemented)

**Reaching it.** The gear button in the toolbar ("Settings (g ,)"), the key sequence `g ,`, or the palette command "Settings". `Esc` or the "← Mail" button goes back; `Esc` closes the open form or dialog first. While Settings is open the mailbox keys (`j`, `k`, `h`, `l`...) are inactive and `?` and `:` still work.

**Providers as cards** on the same violet card style: name, a Local or Cloud badge, a Default marker, model, address, whether an API key is saved ("Saved", "Missing", "Not needed"), and actions Test, Edit, Set default and Delete (with a confirm). Cloud providers have an on/off switch; turning one on first shows an explanatory step, "Review what's shared" (cloud providers receive email content when you use AI features; nothing is sent until you turn one on; "Your system will ask you to confirm."). Go then shows the operating system's own Enable/Cancel dialog as the final confirmation. If that is declined nothing is saved: the form or card stays as it was, the switch goes back to off, and a calm note says "The provider stays off. Nothing was saved." (not an error). Turning one off, and every change to a local provider, needs no prompt. With no providers the page explains the choice and offers Ollama and OpenRouter directly.

**Add and edit.** Presets: Ollama (local, `http://127.0.0.1:11434/v1`, no key, on), OpenRouter (cloud, `https://openrouter.ai/api/v1`, key required, off), and Other OpenAI-compatible. Fields: name (letters, digits, `-` `_`, up to 64; fixed once created; it can't reuse an existing name, and names that differ only by case or `-` vs `_` are refused because they would share one key environment variable), address (http(s), plain http only for this computer, and no username, password, `?` query or `#` fragment), API key, model, capabilities, and for cloud providers a "Turn this provider on" box.
- **API key.** A write-only password field, never prefilled, with "Leave blank to keep the saved key" when one exists. It is cleared from the form as soon as the save call returns, success or not. Keys are bound to the address they were saved for. Whenever a save has an empty key but a stored or environment key exists for a different address, Go refuses (`ErrKeyNeedsReentry`), including for a new provider whose name matches an existing key, and for keys saved before this lock existed. The form explains each case ("You changed the address, so re-enter the API key", "A key is already stored under this name", or "Please re-enter the key once so temail can lock it to this address.") with a button that focuses the field. Listing models shows the same one-time message.
- **Exact signals.** Go marks this case with the test category `key_needs_reentry` and with errors that start with `key_needs_reentry:` (save, list models). The test result shows "Enter the API key again" and an "Enter the key" button that opens the form with focus on the key field.
- **Model.** "Load models" saves your changes first (a cloud provider stays off), then lists the models into a dropdown with "Type a name instead…". If the service can't list models (or the call fails) the field is a plain text box with an explanation.
- **Capabilities.** Structured output, tools and context size, with plain help: "Not sure? Leave these off. temail falls back to asking for JSON in the prompt."
- **Thinking** (local providers only). A select for reasoning before answering: "Model default", "Off (faster)", and Low, Medium, High. Help: "Off is much faster for labeling; temail uses Off for local labeling unless you change it here." The **Detect** button (and picking a model from the list of a saved provider) calls `ModelCapabilities(name, model)`; for a model with named levels they are listed with the default marked "(default)", for a boolean-only model just Model default and Off. When Go reports it unsupported or the call fails, the simple list stays with "Support depends on the model". The select and button are disabled while detecting or saving. The value is saved with the provider and shown on the local card as a badge ("Thinking: off", "Thinking: default", "Thinking: high"). Cloud providers don't show it.
- **Save** and **Save and test**. Test results show friendly copy and a recovery button for every category ("other" also covers an address that redirects: "The address redirected somewhere else. Use the final address."): unreachable, unauthorized, model not found, structured output unsupported, timeout, cloud disabled, no model, keyring unavailable, other. Results are in a polite live region.

Nothing in Settings reads or sends email content; the only network calls are the Test and Load models buttons.

## 11. AI label suggestions (implemented)

Uses `SuggestionService` (Go): `Suggest`, `Status`, `Cancel`, `ApplySuggestions`, and the events `suggest:result` (one per email) and `suggest:done`. The UI never reads or sends email content itself.

**Starting it.** `S`, the toolbar sparkle button, the sparkle button that appears on row hover, "Suggest labels…" in the right-click menu and "Suggest labels (AI)" in the palette. Tooltips show "Suggest labels (S)". Targets follow the same rule as other actions: the selection, else the open message (message pane focused), else the cursor row. Emails without an id yet are skipped. More than 25 emails is refused with a friendly message ("Suggestions work on up to 25 emails at a time. Select fewer"); nothing is cut silently. The job starts as soon as the popup opens, using the default provider (local preferred, decided by Go). With no providers the popup says so and offers "Open Settings"; a turned-off cloud provider (`cloud_disabled`) is refused by Go before anything is sent and shown the same way.

**Popup.** A modal card (same violet card style), mouse first. Header: "Suggest labels", the provider and model with a Local or Cloud badge. For a cloud provider a highlighted note says "This email's content is sent to <provider>" ("These emails' content" for several); for a local one, "Runs on this computer. Nothing leaves it." A progress line, "4 of 7 analysed" (a polite live region, with a thin bar while running), and the final "7 of 7 analysed · 1 failed" when `suggest:done` arrives. Then one page per email: subject and sender, a one-line summary, "Accept all" / "Reject all" for that email, and the suggestion list. Each row has a checkbox, the label name, a target chip from the DTO `target`: "add label" (existing label), "move to folder" with a folder icon (a folder of that name exists, so accepting moves the message; Proton forbids a folder and label with one name; reversible with Undo), or the "new" badge with the tooltip "Creates a new label on Proton (cannot be undone)" (creation is audited but not undoable), a three-bar confidence indicator (with a tooltip and screen-reader text such as "High confidence (90%)"), and the reason in smaller text. Footer: previous and next email buttons, "2 of 7", Cancel and Accept (the Accept label shows the number of ticked labels).

**Ticks.** Existing labels and folder targets with confidence of 60% or more start ticked; new labels and unsure ones start unticked, so nothing creates a label on Proton unless the user ticks it.

**Streaming.** Results render as they arrive; an email still being analysed shows "Analysing…" with the elapsed time ("1:24") and, for local providers, a hint that local models can take a while. There is no client-side timeout (local requests have none; cloud is 120 s per email) and Cancel always works. Events are subscribed before the call, so results that beat the job id are kept, events from other jobs are ignored, and `Status(jobId)` fills in anything missed. A failed email shows its message and code (for example `too_large`); the Go API has no per-email retry (a new job replaces the old one and its results), so there is no Retry button.

**Keys inside the popup** (listed in `?` under "Suggestions"): `j`/`k` (or arrows) move, `Space` or `Enter` tick or untick, `h`/`l` previous and next email, `a` accept all ticked labels, `Esc` cancel and discard (no confirmation), `?` shortcuts. On a focused button `Enter` and `Space` press it. Other mailbox keys are ignored while it is open. Focus is trapped, the list is a `listbox` (`aria-multiselectable`, `aria-activedescendant`, options `aria-selected`), the dialog is `aria-modal`, and focus returns to the opener on close.

**Accept.** Collects the ticked labels per email and calls `ApplySuggestions(jobId, {mid: [names]})` once; Accept is disabled while applying, with nothing ticked, and after a fatal error. Success closes the popup and shows an honest summary such as "Moved 2 messages to Finance, added 3 labels" (or "Added 6 labels to 4 messages") with Undo (it undoes exactly the returned `auditIds`; labels created on Proton stay, and the toast says how many were created). If some emails fail, the popup stays open with each failed email's subject and a friendly line for its code (`create_failed`, `apply_failed`, `move_failed`, …) plus the per-email message from Go (it can include the sanitized Bridge text), clipped to about 120 characters with the full text in a tooltip; emails that succeeded are marked applied and are not sent again. A thrown error is shown in the popup. **Cancel** discards everything and calls `Cancel(jobId)` only while the job is still running.
